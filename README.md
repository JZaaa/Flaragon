# Flaragon

Windows 10+ x64 的个人 PHP 开发环境管理器，使用 Rust、Slint 和 windows-rs，配置编辑器采用 Scintilla + Lexilla。主面板分为“服务”“项目”和“环境设置”，支持托盘、解压发现组件、独立启停、配置和日志。

## 运行与使用

安装与升级 EXE 已生成，当前版本为 **0.2.1**，产物位于 `dist/0.2.1/`。安装包只含软件本体，组件由用户自行解压添加。软件目录通过安装身份、发布清单、程序文件及 EXE 产品版本共同识别，不凭同名文件判断。

- 新电脑使用 `Flaragon-Setup-0.2.1-x64.exe`，选择独立空目录，点击“检查目录”后安装。
- 已正式安装的环境使用 `Flaragon-Update-0.2.1-x64.exe`。先“停止并退出”，再明确选择安装目录，核对完整路径、当前与目标版本后升级；目标软件、编辑器或受管服务未退出时终止更新，不自动停服。
- 升级只替换清单内的程序文件，保留组件、配置、自启选项、项目、数据库和会话文件。兼容范围内支持直接跨版本升级，同版本和降级拒绝，不提供回退。未完成更新只允许使用同一目标发布包续修。
- 源码目录及没有正式安装身份和清单的旧目录不能直接升级。现有使用环境的数据搬迁是独立任务，安装包不会自动搬迁。

完整规则见[安装与升级](docs/deployment.zh-CN.md)。包尚未签名，跨电脑部署及不同 DPI 的完整交互矩阵仍需验证。

本工作区根目录的 `Flaragon.exe` 使用当前源码的开发验证构建，包含启动路径检查与本机目录改名支持；`dist/0.2.1/` 中的固定发布载荷尚未包含这项能力，需要另行发布新版本。

运行环境根目录中的 `Flaragon.exe`，同目录须保留 `lib/Scintilla.dll`、`lib/Lexilla.dll` 和 `licenses`。源码构建的程序位于 `target/x86_64-pc-windows-msvc/release/Flaragon.exe`，直接运行该位置的程序时需传入环境根目录参数：

```powershell
.\target\x86_64-pc-windows-msvc\release\Flaragon.exe (Get-Location).Path
```

- 将可信的 Windows x64 组件包分别解压到 `bin/apache/<包目录>`、`bin/php/<包目录>`、`bin/mysql/<包目录>`、`bin/redis/<包目录>`。支持压缩包多层目录，扫描深度最多 3 层；主面板自动发现变化，也可点击“刷新组件”。“组件详情”显示版本、架构、路径及识别错误。
- 在“环境设置”的“网站服务与默认 PHP”中选择 Apache 和默认 PHP，在“PHP 运行设置”中填写进程数和起始端口。“MySQL 服务”使用带表头的列表，列出使用方式、数据目录名称、版本、端口和操作，状态显示在行下方；扫描只发现 MySQL 组件，服务由用户添加。Apache、PHP、MySQL、Redis 均提供“常用 / 普通 / 停用”三段按钮，点击即可切换。Apache、默认 PHP、项目 PHP 和 MySQL 的版本通过“选择”按钮打开列表面板，支持显示当前选项及取消选择。运行中或被运行网站依赖的设置锁定，停止后才能修改；保存其他服务的环境设置不会重启运行中的服务。修改后点击“应用设置”；“撤销未保存的修改”恢复已保存的设置。修改端口不会自动改写应用的连接配置。
- Apache 同时提供两种入口：“PHP 运行设置”中为各版本配置目录入口的启用状态、HTTP 端口、根目录和监听 IPv4 地址；软件只管理服务和入口配置。项目管理使用统一 HTTP 端口，通过 `/访问标识/` 分配项目的 PHP 版本，根地址提供只读项目导航页。
- PHP 目录入口根目录和项目目录均可点击“选择目录”选择本机文件夹，或填写环境外的盘符绝对路径；环境内相对路径仍可用。网站入口为项目内相对路径，留空使用项目目录本身。项目文件无需搬入软件目录，软件不复制或改写业务文件；网络 UNC、设备路径、父目录跳转和重解析点不支持。
- 在“项目”填写显示名称、访问标识、分组、项目目录和网站入口目录，选择 PHP 或“使用默认 PHP”。CakePHP 的入口可填写 `webroot` 或旧版的 `app/webroot`，其他项目可使用 `public` 或留空。访问标识独立于名称和 PHP 版本；项目可单独启用、允许局域网访问，以及选择是否在导航页展示。列表支持搜索名称、标识和分组，筛选全部、共享和本机项目，并批量设置当前筛选结果的共享状态。
- “启用域名虚拟主机”按项目设置，默认关闭；开启后才生成相应域名配置并参与 hosts 映射。不启用时，域名不作为项目路径访问的前提。项目提供“打开站点”“复制地址”，统一入口提供“打开项目导航页”“复制导航页地址”。移除项目保留文件，MySQL 仍独立管理，应用连接配置由应用自行维护。
- 监听地址默认 `127.0.0.1`。局域网共享时选择本机网卡 IPv4 地址，程序同时保留回环监听用于本机访问和身份确认后的验证；“刷新组件”会重新读取网卡地址。手填 `0.0.0.0` 可监听全部 IPv4 接口，但复制地址需要先选定具体地址。系统防火墙不自动修改，配置说明见 [局域网访问](docs/lan-access.zh-CN.md)。
- 服务页默认显示“全部”，也可按 Apache、PHP、MySQL、Redis 筛选，顶部统计运行服务、项目和组件数量。标签显示对应服务实例数量，包含已停止服务、不包含停用服务；PHP 工作进程池计为一项。筛选不改变全局启停范围。
- 服务列表按“组件 / 实例、使用方式、端口、状态、操作”排列。使用方式读取已保存的环境设置，“常用”显示淡紫色标签，“普通”显示中性文字；停用服务不显示。组件名称左对齐，其余列与表头水平居中，行内图标、文字、状态和按钮垂直居中。
- 服务主名称采用 `bin/<模块>/<自定义文件夹>` 中的文件夹名，保留大小写、空格与中文。解压包内部的 `bin`、`Apache24` 等嵌套目录不作为名称；实际版本放在副标题。同一 MySQL 包的多个实例用副标题中的数据目录名称和独立端口区分。建议放入组件前确定文件夹名；已关联组件的目录重命名尚不自动迁移包引用与数据库版本绑定。
- “配置 / 编辑配置”打开实例实际加载的完整原生配置文件，窗口标题显示完整路径。支持 UTF-8 文本、注释、配置节和普通原生参数；组件安装目录内的原始配置不修改。MySQL 每个实例使用独立 `my.ini`。文件中的 `FLARAGON INSTANCE / PROJECTS` 标记段由环境设置和项目页维护，不能手改或在段外覆盖实例归属字段；其余内容在应用和重启时保留。
- “启动常用 ▾”的主按钮启动常用服务，下拉菜单“启动全部”启动常用及普通服务；停用服务不显示、不计数且不能启动。启动 Apache 会带起启用项目所需的普通或常用 PHP；依赖 PHP 被停用时，在启动批次执行前提示并拒绝。选中服务后可单独启停、重启、编辑用户配置或查看日志；右键服务行可打开对应实例的快捷菜单，忙碌或不适用的操作禁用。共享 PHP 被 Apache 使用时，停止操作会提示依赖；重启 PHP 会受控重启入口。
- Apache 运行时提供“重加载配置”：读取完整 `httpd.conf`、校验候选配置、备份并发送 WinNT MPM 重加载事件，再用新诊断地址和站点请求验证生效；主进程、PHP 和数据库保持运行。无效候选配置恢复为已应用文件；应用后失败则尝试恢复并报告结果。PHP、MySQL、Redis 不提供完整文件配置热加载菜单，需使用“重启”或配置窗口中的“检查并应用”。仅重加载 Apache 不应用其他组件的文件修改。
- 关闭主窗口保留托盘和服务；点击托盘或再次运行同一环境的 `Flaragon.exe` 恢复。“停止并退出”先正常停止服务，再退出管理器。数据库关闭失败时保留进程并报告错误。
- 完整停止并退出后，可在本机改名或移动整个环境目录，再从新位置打开 `Flaragon.exe`。启动路径检查以当前环境根目录统一解析内部相对路径，检测 `config/paths.json` 记录的根目录变化，仅更新实例原生配置及管理段基线中的旧路径前缀；用户自定义参数和环境外站点路径保留。旧运行配置快照失效，服务须重新启动验证。路径更新备份保存在 `runtime/path-backups`，中断后先恢复再重试；未确认服务退出或路径归属不明确时拒绝改写。初始化失败仍保留单实例锁，可刷新重试或退出面板，不留下无法退出的后台窗口。
- “环境设置 → 启动设置”提供“开机启动 Flaragon”和“软件启动后自动启动常用服务”，默认都关闭，点击“保存启动设置”单独保存。软件自启在当前用户登录 Windows 时运行环境根目录的 `Flaragon.exe`；两个开关独立，关闭软件自启不会改变常用服务自启。服务自启从下次新进程启动起生效，手动打开软件也会触发；保存设置、刷新组件和恢复托盘窗口不触发。常用服务使用与“启动常用”相同的依赖检查和失败恢复逻辑，普通 PHP 仍可能作为 Apache 依赖启动，停用依赖会阻止启动批次。失败显示在面板中，不循环重试。
- `.localhost` 域名通常由浏览器解析到本机。“域名映射”提供 `.test` / `.localhost` 的 hosts 预览和受限提权入口，仅修改本环境标记块，冲突时拒绝覆盖。真实系统 hosts 写入尚未验证；开发测试没有读取或修改系统 hosts。

PHP 的扩展由各版本自己的用户 ini 控制。例如在对应 PHP 的“配置”中加入下列内容后点击“检查并应用”，即可加载该版本包内的数据库驱动；PDO 与 mysqli 的三版本连接组合已经实测：

```ini
extension=php_mysqli.dll
extension=php_pdo_mysql.dll
```

新建 MySQL 数据库仅监听回环地址，`root` 初始密码为空，请在数据库中自行设置。管理器通过已确认身份的 Windows 正常关闭事件停止 MySQL，不要求保存数据库密码。Redis 单实例仅监听回环地址，默认启用 AOF 与 RDB；应用需自行选择键前缀或逻辑数据库。

## 配置与数据

```text
bin/                       组件二进制，不存业务数据
config/app.json            项目、实例、端口与默认版本
config/startup.json        软件登录启动与常用服务自启选项
config/services/php/<包标识>/php.ini    PHP 实际加载的完整配置
config/services/mysql/<实例名>/my.ini   MySQL 实际加载的独立配置
config/services/apache/httpd.conf       Apache 实际加载的完整配置
config/services/redis/redis.conf         Redis 实际加载的完整配置
config/services/**/                    管理段基线、应用备份与编辑前备份
config/overrides/          完整配置首次建立时的用户内容来源；不作为编辑入口
config/app.backup.json      上一份应用配置备份
config/paths.json           当前环境根目录记录；启动时检查变化
config/environment.id       hosts 标记块的环境身份
config/hosts.backup         用户实际应用 hosts 时生成的备份
www/                       项目代码
data/mysql/<x.y>/<数据目录名称>/  独立 MySQL 数据目录
data/mysql/<版本>/<数据目录名称>/.flaragon-binding.json  数据目录与具体构建绑定
data/redis/                Redis 持久化文件
runtime/generated/         候选配置、诊断脚本；不作为持久配置编辑入口
runtime/state/             进程身份、已应用配置、辅助操作结果
runtime/path-backups/      路径更新的恢复备份
runtime/temp/              临时文件和 PHP session
logs/                      各实例日志
```

配置以所选组件包附带的原生模板初始化，保留参数、注释和配置节：PHP 优先使用包内 `php.ini`，否则使用 `php.ini-development` / `php.ini-production`；Apache 使用 `conf/httpd.conf`；Redis 使用 `redis.conf`。安装目录原文件不修改，副本中的实例目录、端口、日志和必要模块由管理器适配。模板来源写在文件中。已有的简短配置在首次打开或应用时补齐，已有参数优先，补齐前文件保留备份；之后以实例文件为准，不重复导入模板或覆盖片段。打开文件补齐不代表运行进程已经加载，仍需保存并应用。不要删除 `.managed.json` 基线文件。

当前 MySQL 5.7.44 / 8.0.44 ZIP 包未附带 `my.ini` 模板，因此编辑器明确显示“此组件包未附带配置模板”；展示独立实例实际加载的配置，可添加原生参数，但不是全部 MySQL 参数清单。若包内提供 `my.ini` / `my.cnf` / `my-default.ini` / `my-default.cnf`，首次建立实例配置时会读取该模板。没有模板时不伪造发行包原始配置。

环境设置只应用已停止服务的修改，不停止或重启其他运行服务。项目路由和完整原生文件配置应用经过预检查、候选配置生成、备份、正常停止、应用、运行验证；失败时尝试恢复文件和服务，并明确报告恢复结果。Apache 使用 `-t`、PHP 使用隔离的加载检查、MySQL 使用 `--verbose --help` 预检查；Redis 的实际语法和运行生效在启动时验证。停止状态下保存不代表已经运行生效。手动修改完整文件后需在面板配置窗口中应用或重启相关服务；尚未自动监测配置文件变化。

完整文件编辑不使用普通参数白名单，但仍校验实例隔离：端口、数据目录、控制通道等由面板维护；文件引用须使用环境目录内的绝对路径。外部路径、额外 Include、动态变量、命令管道及部分插件加载和认证配置尚不支持。配置文件大小上限为 1 MiB；配置快照不用于保存凭据。

网站业务目录通过项目和 PHP 根目录字段单独配置，可使用环境外的本机路径；上述完整配置编辑的内部文件限制不作用于这些业务目录字段。

MySQL 数据目录按检测版本 x.y.z 的 x.y 分层，例如 5.7.44 对应 5.7、8.0.44 对应 8.0；不同版本可以同名，同版本大小写不同的同名目录也视为冲突，不允许两项服务使用同一数据目录。新增行显示“新增 · 未保存”；下方显示完整路径，目录存在时红字提示，使用历史数据需要确认且原构建必须匹配。已保存的数据目录名称和版本固定，需要更换时移除后重新添加；移除前确认并告知数据保留位置，数据需用户自行到该位置删除。

不要复用其他 MySQL 版本的数据目录，不要删除 `.flaragon-binding.json` 来尝试切换版本。从环境设置移除 MySQL 服务不会删除其数据。管理器不提供数据库升级、导入导出或迁移助手。加载配置时忽略项目中的旧 `mysql` 字段，保存时不再写出；环境设置中的 MySQL 服务配置保留。
