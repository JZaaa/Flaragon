# Flaragon：Windows 开发环境设计

## 1. 已确认需求

- 仅支持 Windows 10 及以上的 x64 系统，不提供 32 位版本；面向自用，优先多版本并行、配置可靠生效和轻量简洁。
- 技术栈为 Rust 核心 + Slint 主界面 + Scintilla 配置编辑器，windows-rs 调用 Windows 系统接口。
- 操作方式优先参考 Laragon：小面板、托盘、一键启停、版本菜单、目录扫描。
- PHP 7.4、8.3、8.5 可被不同项目同时使用。
- 环境路径及父目录、组件、项目、网站入口和 MySQL 数据目录均禁止包含中文，在创建或调用组件前明确拒绝。空格目录仍支持，项目显示名称、分组和配置注释允许中文。
- MySQL 5.7 与 8.x 可同时运行。
- Redis 纳入首版，按单版本、单实例管理，不做多版本选择或并行运行。
- 用户下载组件压缩包，解压到约定目录即可发现；不依赖软件商店或固定下载源。
- 便携迁移可以考虑，但不是首个实现目标；先保留结构上的可迁移性。
- 项目终端是后续可选功能，与便携迁移一样不纳入首版实现和验收。
- 修改项目根目录、运行版本和配置后，能明确判断是否真正生效。

本文描述当前有效的需求与技术方案，不作为验证结果；实际能力以代码及对应验证证据为准，基本使用见 [README.md](../README.md)，待办与待确认问题集中在 [PLAN.md](../PLAN.md)。系统下限为 Windows 10，仅支持 x64，以 Windows 10/11 x64 验收，具体组件构建和扩展组合需要通过实机验证确定。便携迁移属于可选功能，不作为首版交付条件。

正式发版及版本号由用户指定。用户明确要求不发版修复时，可以独立的同版本修复包更新指定基线构建，包括原始正式安装或已归档补丁的结果构建，保持产品版本、配置与数据，使用独立构建标识区分修复结果；未携带原始构建绑定的普通同版本升级仍拒绝。修复绑定与中断续修规则见[安装与升级](deployment.zh-CN.md#专用同版本修复)。

安装与升级使用同一个完整 Setup 包，按目标目录识别新安装、升级或中断续修。兼容范围由 release-policy.json 显式指定 minimum_version 和 excluded_versions，支持范围内跨版本直升；同版本仍须明确绑定构建，降级拒绝。现有已发布归档保持自身规则，不因源码修改而改变。当前配置 schema 1 兼容读取，升级不改写配置或业务数据；其他格式在写入前拒绝。

0.0.5 统一包用于新安装、兼容范围内直升及原始 0.0.5 的同版本覆盖升级。update-base.json 绑定原始完整清单与构建身份，允许更新目标包的升级兼容范围，仍保持产品版本、配置格式、程序集合和配套依赖。重复升级和其他同版本构建拒绝；中断必须使用同一包续修。原始包独立归档。

### 开发与验证边界

开发相关的源代码、下载、依赖缓存、构建产物、临时文件、测试项目、服务配置、数据和验证证据只保存在 `D:\flaragon_dev` 内。禁止修改外部项目，禁止扫描、读取、复制或操作其他环境的数据库等服务数据，也禁止通过网络连接访问或控制其他环境实例。真实组件验证使用项目内独立准备的发行包和新建数据；缺少组件时保留未验证状态。

既有通用工具链与系统 SDK 仅供只读调用，可配置的缓存和输出须定向到项目内。开发测试不实际修改系统 hosts、证书信任、注册表或系统服务；相应功能的真实集成验证不因模拟测试通过而视为完成。以下产品功能设计不扩大开发操作边界，具体执行约束见 AGENTS.md。

## 2. 实现方向

独立实现一个小型环境管理器，参考两者的操作和服务编排思想。首版包含 Apache、PHP、MySQL、Redis、项目配置、简洁面板和日志。PHP 和 MySQL 支持多版本并行；Redis 按单实例管理。项目终端、便携迁移均为后续可选功能。

技术栈为 Rust + Slint 1.18.1 + windows-rs，仅发布 Windows x64 程序。主界面使用 Slint 软件渲染，按服务、项目、环境设置组织；系统托盘与 Windows 窗口保持桌面交互。配置、日志和诊断使用独立 Scintilla 5.6.7 原生窗口，Lexilla 5.5.4 提供 INI 与配置文件高亮。核心逻辑与界面分离，编辑窗口在独立线程运行，通过有界通道向后台提交保存与应用任务。实际启动速度、内存和包体积以 Release 构建测量为准。

Slint 采用 Royalty-free 2.0 许可，顶层“帮助 → 关于 Flaragon”包含官方 AboutSlint 控件；第三方声明随程序分发。编辑器提供行号、查找替换、跳转、撤销重做和自动换行；磁盘配置变化时拒绝覆盖，失败保留编辑内容。PHP、MySQL、Redis 的正式配置保存在各自组件包内，Apache 配置独立保存；候选校验、备份、应用与恢复流程由核心处理。

管理器本身不需要浏览器内核。普通组件作为子进程运行，默认不注册 Windows 服务；修改 hosts 等系统操作由小型提权助手完成，主界面不常驻管理员权限。

### 软件与常用服务自启

软件自启和常用服务自启为两个独立选项，默认关闭；两者互不依赖，关闭软件自启不改变常用服务自启。选项位于环境设置的启动设置卡片，单独保存至 `config/startup.json`，不参与服务配置应用，也不因保存而启停服务。

软件自启通过当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 登记，在该用户登录 Windows 后启动环境根目录的 `Flaragon.exe`，不要求管理员权限。每个环境使用包含规范化根目录的独立值名，完整可执行路径加双引号，软件从自身目录识别环境，不依赖登录时的工作目录。启用前检查文件与路径边界，以及 Run 命令的 260 字符限制；只读写本环境的值，不枚举其他启动项。内容冲突时拒绝覆盖或删除。登记更新后读回校验，再原子保存选项；失败尝试恢复先前登记并报告结果。Windows 对启动应用的禁用或策略限制不由本程序绕过。参考 [Windows Run 登录启动说明](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)。

新桌面管理器进程取得环境锁、恢复进程身份并完成首次组件扫描后，在后台按已保存设置启动常用服务。此逻辑只执行一次；手动启动软件同样适用，托盘恢复、再次双击已有环境、刷新组件和保存设置均不重复执行。常用服务自启仅由自身选项控制，不依赖软件登录启动开关或系统登记状态；登录登记异常单独在启动设置中提示。常用服务复用现有批量启停、依赖校验、进程身份与失败清理流程；启动错误保留面板用于诊断，不自动循环重试，不把组件注册为系统服务。

开发隔离模式将登录启动登记替换为环境内 `runtime/state/startup-registration.json` 夹具，界面不展示开发验证说明，也不将模拟登记显示为系统登记成功；Windows 登记封装同时拒绝带 `FLARAGON_DEV_ROOT` 的访问。夹具验证不等同于系统登录验证，也不修改系统启动应用设置。环境移动后的路径重定位不属于此功能，需在原位置关闭自启，在新位置重新设置。

构建采用 Rust stable 的 x86_64-pc-windows-msvc 工具链、Cargo、对应的 MSVC 构建工具与 Windows SDK。首次验证工具链后固定 Rust 和依赖版本，并提交 Cargo.lock，避免构建随环境漂移。发布前检查 CRT 等实际动态依赖；目标机器不需要安装 Rust 编译器。Rust 工具链的构建环境要求和应用最低 Windows 10 运行要求分别验证。

UI 线程只处理窗口消息、控件和轻量状态更新。目录扫描、版本探测、健康检查、服务启停和日志读取在后台执行，通过有界消息通道与窗口通知传回结果；限制日志缓冲和刷新频率。首版根据实际 I/O 需求决定是否引入异步运行时，不为每个功能堆叠框架。

服务页与环境设置页共享后台“刷新组件”操作，自动发现与手动刷新均更新设置选项。界面按组件身份合并新增项并保留已有选项顺序、选择及未保存的输入；刷新不应用表单、不启停服务。MySQL 发现组件与添加服务保持分离。

Redis 用户配置允许 `requirepass`，管理器解析 Redis 引号与转义语法，通过同一连接先 AUTH 再发送健康检查或关闭命令。进程记录保存启动时密码的加密副本，改密时先用运行密码正常关闭旧进程；恢复后仍以进程身份和端口归属为控制前提。认证失败不继续发送控制命令，也不强制结束数据库。ACL、复制凭据与控制命令重命名不在当前支持范围。

运行凭据、磁盘已应用配置快照、Redis 配置备份及路径事务备份使用 Windows 当前用户 DPAPI 保护，兼容读取旧的无密码恢复记录。原生配置和候选配置仍为组件可读取的文本；错误与日志不得输出密码。加密恢复记录依赖同一 Windows 用户，不构成跨机器迁移支持。

将 Win32 API、句柄、回调和 unsafe 操作集中到 Windows 适配层，以明确的所有权和析构逻辑管理资源；进程句柄关闭不等同于结束进程。普通业务模块使用安全 Rust，禁止跨 Windows 回调边界传播 panic。验证中文目录拒绝提示、空格路径、高 DPI、窗口缩放及托盘恢复行为。

Laragon 当前公开仓库列出打包资源和 laragon.exe，不能据此假定完整 GUI 源码可以直接用于二次开发。FlyEnv 提供源码，可研究其实现；本项目首版采用独立实现，若后续复用代码则记录来源并保留相应声明。

## 3. 三个核心对象

| 对象 | 作用 | 例子 |
| --- | --- | --- |
| 组件包 Package | 解压后的二进制版本；不包含业务数据 | php-8.3.x、mysql-5.7.x |
| 运行实例 Instance | 包引用、独立配置、端口、数据和进程身份 | mysql57-dev、mysql8-dev |
| 项目 Project | 访问标识、可选域名、代码目录、文档根目录和 PHP 配置 | legacy、api |

同一 MySQL 包可以建立多个独立实例，各实例的配置在包内分开保存，数据目录和端口分别管理。每个 PHP 包使用程序旁的一份 php.ini 和一组 worker；网站与 CLI 使用同一个包时共用这份配置，不提供同包多套 ini。

项目必须明确选择 PHP 包，不提供“使用默认 PHP”选项；未选择时拒绝保存。加载已有继承配置时固定为当时的默认 PHP 包，后续修改默认选择不改变项目。项目导航页显示所选包的实测 PHP 版本和包名称。

MySQL 服务在环境设置中独立管理，不与项目关联。应用在 .env 或自己的配置文件中使用正确的地址、端口、数据库和凭据，管理器不改写应用的连接配置。

### MySQL 数据目录检查与接入

环境设置为已保存、已停止的 MySQL 服务提供“检查目录”和“接入数据”。检查由用户主动触发，常规页面刷新不反复扫描已有目录。状态区分未创建、空目录、已绑定、未绑定的已有数据、绑定不匹配、结构不完整、初始化未完成、接入未完成及绑定无效。未绑定的目录可以在明确确认后登记服务，普通启动仍拒绝使用，须通过独立接入操作。

接入使用已经放在本实例 `data/mysql/<x.y>/<名称>` 内的数据，不读取或复制外部来源。确认页显示完整目录、所选版本和 `mysql_upgrade_info` 中的可用线索，要求用户填写已核实的来源完整版本，并分别确认来源正常停止、完整备份与实例配置匹配。版本线索缺失不会冒充已识别来源；不一致时停止接入。当前结构检查识别默认 InnoDB 布局的 `ibdata1`、系统目录及对应版本系统表文件；特殊表空间布局需要单独处理。检查结构不等于校验所有数据页或业务表。

确认前后的目录树及组件元数据、服务设置和候选配置必须保持一致；目录树拒绝重解析点，并限制条目数、深度与检查时间。复核所属进程停止、独占数据文件检查和端口可用性后持久记录接入未完成标记，使用实例配置启动 MySQL，确认所属进程端口及实际版本，再正常关闭。MySQL 8.x 接入通过 `--upgrade=NONE` 禁止启动升级；不支持该参数的构建会失败并保留数据。验证期间禁用事件调度和复制自动启动。启动仍可能执行恢复并写入文件，用户须保留独立备份。

启动及正常关闭全部成功后，原子创建 `.flaragon-binding.json`，记录格式版本、组件标识、完整版本和初始化或接入来源；兼容读取旧字符串绑定。并发出现的绑定不覆盖。接入失败保留数据和未完成标记，允许正常停机后重新检查、确认并重试，不初始化、不升级、不强杀。初始化使用独立未完成标记，不能把失败的新库当成完整旧数据接入。绑定记录不构成完整性或兼容性证明，接入不等于验证完整业务应用。

## 4. 多版本 PHP

使用一个 Apache 同时提供版本目录入口和受管理项目入口。Windows PHP 使用 php-cgi.exe，优先检测和使用 NTS 构建；两类入口共用每个 PHP 包的进程池，不引入 Caddy 或 Nginx。

版本目录入口在环境设置中按 PHP 包配置启用状态、HTTP 端口、根目录和监听 IPv4 地址。此模式仅提供服务与配置，不要求在软件中登记项目，也不承担目录内项目的管理职责。

开发站点默认开启 Apache 目录浏览，包括 PHP 版本目录入口、受管理项目路径和已启用的项目域名入口。目录中存在配置的首页文件时优先打开首页，否则列出可访问的文件与子目录；项目自己的 `.htaccess` 可覆盖目录索引及重写规则。Apache 必须加载 `mod_autoindex`，目录浏览沿用各入口的访问权限。统一入口根地址仍显示项目导航页。

受管理项目共用 HTTP 端口：根地址为只读项目导航页，`/访问标识/` 映射到项目的网站入口目录，并按项目配置选择 PHP。访问标识独立于显示名称、分组和 PHP 版本；无匹配项目时返回 404。导航页仅展示启用且选择展示的项目，局域网监听下仅展示允许局域网访问的项目，支持搜索和分组；站点链接相对于当前入口，不硬编码机器 IP。隐藏导航项不关闭直接路径访问。

每个项目提供“启用域名虚拟主机”，默认关闭，只有明确开启的项目才生成域名虚拟主机并参与 hosts 映射。域名入口是可选配置，不作为 IP 路径入口的前提。

监听默认仅本机；用户可选择具体网卡 IPv4 地址用于局域网，同时保留回环监听以执行本机诊断。目录入口的监听地址独立配置；受管理项目还可单独限制本机访问。PHP FastCGI 仅监听回环；MySQL 与 Redis 的监听地址由用户在原生配置中选择。新建项目默认勾选允许局域网访问，已有项目保持原值。软件不自动修改防火墙、应用连接参数或项目文件。

以下为两种入口同时使用时的示例配置，不代表正在运行的端口：

```text
Apache
  192.168.1.50:8074/<目录>/ → 指定根目录，PHP 7.4
  192.168.1.50:8083/<目录>/ → 指定根目录，PHP 8.3
  192.168.1.50:8080/        → 项目导航页
    /legacy/                → 项目入口目录，PHP 7.4
    /api/                   → 项目入口目录，PHP 8.3
    /next/                  → 项目入口目录，PHP 8.5

PHP 后端：127.0.0.1 上的独立 FastCGI 进程池
MySQL / Redis：由应用按各自连接配置访问本机实例
```

这些端口是示例初始值，不依靠版本号硬编码。用户可修改；启动前检查冲突，外部程序占用时提示原因，不终止外部程序，也不静默更改数据库端口。

Apache 加载 mod_proxy、mod_proxy_fcgi，并按站点生成处理器配置；使用 php-cgi 后端时显式考虑 ProxyFCGIBackendType GENERIC、脚本路径映射及 PATH_INFO，必须通过 Windows 实测。mod_proxy_fcgi 不负责启动后端进程，管理器负责启动、健康检查和回收。

每个 PHP 实例具有明确的 php.ini、附加 ini 扫描目录、扩展目录、临时目录、session 目录和日志。启动环境显式设置，避免继承机器上的 PHPRC、PHP_INI_SCAN_DIR 导致串配置。

服务探测不能只检查监听端口：还需执行隔离的诊断请求确认 PHP_VERSION、加载的 ini 和实例标识。组件发现保留 PHP 程序返回的完整 PHP_VERSION，包括预发布或自定义构建后缀，不从文件夹名推断，也不截取为三段数字。HTTP 诊断严格比较完整版本，失败时显示预期与实际版本。探测入口限本机并使用临时随机标识，不向普通项目公开 phpinfo。

FastCGI 验证需要覆盖单进程请求行为和长请求阻塞情况。正常开发所需的并发通过受管理的多个 worker / 后端端口池实现，尤其验证浏览器并发请求和应用调用自身 HTTP 接口；不能仅凭页面能打开就认定完整支持。

后续可选的项目终端可在新开的终端进程中设置独立 PATH，使用所选 php.exe 执行 Composer、artisan、测试等命令；不修改系统 PATH。首版不提供该功能，也不要求管理 Composer。管理器内部调用 PHP 使用完整可执行文件路径。

## 5. 多版本 MySQL

每个实例独立管理 basedir、datadir、port、配置、PID 标识、日志和临时目录；MySQL 8.x 如启用 X Protocol，也必须分配独立端口。按具体版本能力生成配置，不能把同一份 my.ini 原样用于所有 5.7 / 8.x。

MySQL 的 `bind-address` 是用户可编辑参数，不属于实例管理段。新建配置无已有监听设置时写入 `0.0.0.0`；已有值保留并移入可编辑区域。候选配置由所选组件检查，按其报告的有效地址预检端口，启动后核验对应监听者身份；运行记录保存实际监听地址，健康检查使用所属监听地址，不假定回环始终可达。配置保存仅正常重启被修改的运行实例，保留数据和其他服务。

MySQL 5.7 和早于 8.0.13 的构建接受单个地址；较新构建可配置逗号分隔的多个具体地址，通配地址不能与其他地址混用。`0.0.0.0` 表示所有 IPv4 接口，IPv6 和 `localhost` 的可达性取决于用户配置。规则以 [MySQL 监听说明](https://dev.mysql.com/doc/refman/8.0/en/server-system-variables.html#sysvar_bind_address)及组件校验为准，实测范围见 PLAN.md。

启动时显式指定实例配置，防止读到全局配置。新实例只在新建且空的数据目录执行初始化；目录已有内容但初始化不完整时停止并报告，不自动清空。

数据目录为 data/mysql/<x.y>/<名称>，x.y 从所选组件检测到的 x.y.z 版本号取前两段，不同版本可同名，同版本名称不区分大小写去重。扫描只发现组件，不自动创建 MySQL 服务。数据目录绑定具体组件包和构建，保存后名称和版本固定。目录不存在时提示首次启动创建；存在时红字提示，复用需明确确认并核对绑定，非空无绑定目录拒绝普通启动，须通过明确的已有数据接入流程；损坏目录拒绝使用。移除服务只移除配置，不删除数据，确认框列出需用户自行删除的目录。禁止将 5.7 的数据目录交给 8.x 当作普通“切换版本”使用，也禁止多个实例共享同一个数据目录。数据库升级和跨大版本迁移属于单独操作，首版采用备份、逻辑导出和导入流程。

运行状态需要进程身份与服务探测共同确定。启动时检查进程退出码和错误日志。停止时执行有权限的正常关闭，等待进程退出；超时显示失败，不把强杀当作正常停止，不因退出管理面板而直接强杀数据库。

凭据不能放入日志或命令行参数；迁移包中默认不保存机器绑定的凭据密文，迁移后支持重新输入。当前正常关闭使用经进程身份校验的 Windows 命名事件，不需要保存数据库控制凭据；应用连接凭据仍由应用自行管理。

### 5.1 Redis 单实例

Redis 的 `bind`、`protected-mode` 由用户在原生配置中编辑；保留已有值，新建且没有监听设置时使用 `bind 0.0.0.0`。监听地址与认证、保护模式分别配置；管理器不自动放宽认证或防火墙。健康检查及正常关闭使用启动记录中的地址，发送命令前核对监听者归属。

Redis 属于首版核心组件，提供发现、启动、停止、重启、状态、配置和日志入口。不提供多版本切换菜单或多实例创建功能；检测版本仅用于兼容性诊断。多个项目可以连接同一个 Redis 服务。

默认监听 127.0.0.1:6379，端口可配置；redis.conf 保存在组件包内，数据和日志与组件包分离。使用方式为“常用 / 普通 / 停用”：常用参与两种批量启动，普通仅参与“启动全部”，停用不显示、不计数且不启动；运行中锁定设置。端口被其他程序占用时明确提示，不结束外部进程。

健康检查结合受管理的进程身份和 Redis PING 响应；配置变更经受控重启后验证。正常停止使用经身份确认的目标服务的 SHUTDOWN，遵循已配置的持久化策略并等待进程退出，失败时保留错误状态，不把强杀或清空数据作为普通停止操作。若启用 RDB/AOF，验收重启后的数据恢复。

项目使用自己的连接参数和键前缀区分数据；管理器不自动修改业务配置，也不自动执行 FLUSHDB / FLUSHALL。PHP 的 Redis 扩展属于各 PHP 版本自己的扩展依赖，需要匹配版本、架构及 TS/NTS，不能因共享 Redis 服务就共用扩展 DLL；现有扩展配置或应用自带的 PHP 客户端可继续使用。

Windows 发行包需要单独选型和实测，不能假定 Redis 官方提供与 PHP 相同形式的 Windows ZIP 包。官方 Windows 安装资料列出 Memurai、WSL 等路线；首版验证在本项目内独立准备、可直接在 Windows 运行的兼容构建，记录来源和能力，不借用其他环境的程序、配置或数据，当前已实测 redis-windows 7.4.3 MSYS2 x64 社区构建，未验证组合与待办见 PLAN.md。默认架构不引入 Docker/WSL，也不将未经验证的第三方构建标记为官方包。

## 6. 本地目录与可选便携能力

面向独立使用目录的安装 EXE、升级 EXE 及发布版本管理见[安装与升级方案](deployment.zh-CN.md)。安装包仅含软件本体，升级必须明确指定安装位置，并核验安装身份、发布清单、EXE 产品版本和程序文件；目标软件、编辑器或受管服务未退出时提示并终止，不支持版本回退。完整程序包在经验证的兼容范围内直接跨版本升级，未完成操作只允许向同一目标版本续修；配置、组件与业务数据保持独立。软件部署与数据库迁移分开，具体兼容范围依据发布策略及对应验证证据确定。

每次发版及发布版本号由用户明确指定；日常开发构建不自动变更产品版本。[CHANGELOG.md](../CHANGELOG.md)按版本保留最终功能概述，顶部“未发布”部分用于当前开发版本，不记录开发调试过程。发布完成后该版本日志固定，标题、条目及顺序均不得修改；下一次开发在顶部新增“未发布”部分，保留全部已发布日志。

以下为当前目录职责；备份文件和运行配置在相应操作发生时生成。

```text
Flaragon/
  Flaragon.exe
  bin/
    apache/<package-id>/
    php/<包目录>/<实际程序目录>/php.ini
    mysql/<包目录>/<实际包根目录>/instances/<实例ID>/my.ini
    redis/<包目录>/<实际程序目录>/redis.conf
  config/
    app.json
    startup.json
    services/apache/httpd.conf
    overrides/apache.conf
  data/mysql/<x.y>/<name>/
  data/redis/
  www/<project>/
  runtime/
    generated/
    state/
    temp/
  logs/
```

用户配置优先存相对根目录的路径，运行时由 Layout.root 统一从 Flaragon.exe 所在目录解析；开发构建可显式指定环境根目录。进程记录中的程序与配置路径、已应用快照的文件键使用环境内相对路径，恢复时解析为当前绝对路径。组件要求的绝对路径由此根目录生成，不将可变环境目录编译进程序。

启动时后台检查 config/paths.json 中的根目录记录。完整停止后改名或移动整个本机目录时，将原环境内的项目与目录入口转为相对路径，更新实例原生配置、管理段基线及首次配置片段中确属原根目录的路径前缀；外部业务目录和相似名称的目录保持原值。兼容没有路径记录的环境，从本目录内运行快照键和固定管理字段识别一致的原根目录，不访问旧位置。先检查记录的服务已退出，再备份、原子更新与提交新根目录；失败恢复，中断记录在下次启动时恢复后重试。无变化的文件不写入。旧运行快照不作为新位置已经生效的证明，服务启动仍需原生语法及健康验证；跨机器依赖、系统登录启动项和 hosts 不由此本机路径检查自动迁移。

环境锁由桌面窗口持有至事件循环退出，后台初始化失败不释放锁。失败状态接受刷新重试及退出；后台意外退出时也允许结束面板，保留服务原状，不强制终止数据库。

PHP 目录入口根目录和项目目录均允许使用者通过本机文件夹选择器选择目录，或填写盘符绝对路径；环境内相对路径仍可使用。项目代码目录与 Web 文档根目录分开，网站入口填写项目内相对路径，例如项目为 `E:\work\api`，入口为 `webroot`。不复制、移动或改写项目文件。网络 UNC、设备路径、父目录跳转和重解析点拒绝使用；配置、组件、日志、数据库及运行文件仍限定在环境目录内。

开发、测试及 AI 调试使用 `FLARAGON_DEV_ROOT` 限定环境及业务目录的范围，在文件访问前校验；开发目录选择器也以此目录作为浏览边界。`scripts/env.ps1` 只设置当前进程及其子进程环境，正常桌面运行不设置该变量。验证环境外目录时，在本项目内创建独立环境和同级站点夹具，不读取本项目外的真实项目。跨机器迁移仍为后续功能。

迁移流程：正常停止服务 → 确认数据库退出 → 复制目录 → 在目标电脑检查依赖 → 重建域名映射与运行配置 → 启动并诊断。不能复制运行中的数据库目录当作完整备份。

便携不代表目标机器完全无需准备：PHP/Apache 可能需要对应 Visual C++ 运行库；域名 hosts 记录和本地证书信任需要在目标机器重建。Apache 官方不提供 Windows 二进制发行包，需识别兼容的 Windows 构建分发包。

## 7. 目录发现

启动扫描、手动刷新和文件变化去抖扫描并存。识别可执行文件位置，而非只相信文件夹名称；允许常见压缩包多一层目录的结构，但限制扫描深度。

检测结果至少包括版本、架构、PHP TS/NTS、关键文件、必需模块及无法加载的依赖。PHP 探测将线程安全标志统一输出为 0 或 1，兼容整数与布尔类型的 PHP_ZTS。失败项目仍显示在列表中，并给出可操作的原因。

组件扫描不等于启动服务。版本探测设置超时、输出长度限制并使用隔离环境。组件目录来自用户主动放入的可信包；不在扫描中自动下载或执行安装器。

已配置的组件目录缺失时保留服务记录并显示“组件缺失”，不自动清理。服务行和右键菜单提供手动移除入口；环境设置的“缺失组件”同时列出已停用的缺失服务。确认后只移除所选服务记录，不删除配置、项目或数据；MySQL 按实例移除，确认框显示保留的数据位置。后台重新扫描，组件已恢复、仍存在但探测失败、服务仍运行或运行中的 Apache 依赖相关 PHP 时拒绝移除。

PHP 被项目引用时，移除入口可弹窗选择另一个已安装且启用的 PHP 包，确认受影响项目后批量切换；停用项目也包含在内。环境设置和服务右键菜单同时提供独立的批量切换入口，便于更新包前统一调整项目。无项目引用的默认 PHP 在移除后清空，对应目录入口随服务记录移除。缺失组件期间允许保存项目的版本切换，缺失组件及相关 Apache 原生配置暂不生成，明确提示尚未校验；恢复组件或完成引用调整后，应用及启动仍执行原生配置与运行验证。

配置入口编辑实例实际加载的完整原生文件，保留注释、配置节与自定义参数。PHP 使用 php.exe 同目录的 php.ini，Redis 使用 redis-server.exe 同目录的 redis.conf，MySQL 使用实际包根目录下 instances/<实例ID>/my.ini；多实例不能共用一个可变配置文件。Apache 使用 config/services/apache/httpd.conf。程序目录按实际可执行文件位置识别，支持发行包嵌套目录。runtime/generated 只承载候选配置和诊断文件，不作为编辑入口。

完整文件中的实例归属和项目路由由明确标记的管理段维护，管理段变更通过环境设置和项目页进行；其余原生配置内容持久保留。应用前检测管理段冲突和路径边界，不静默覆盖手改的管理字段。普通参数不使用白名单；不能确认归属的间接文件引用、插件执行和控制通道变更明确拒绝。

PHP、MySQL、Redis 优先保留当前包内目标配置的自定义参数；目标文件不存在时从当前包模板建立，PHP 使用开发模板或生产模板，Redis 可使用 redis.windows.conf，MySQL 可使用包根目录中的 my.ini、my.cnf 等模板。模板原文保留，正式配置中的管理段维护目录、端口和日志引用，基线与配置备份也保存在正式配置旁。没有模板时明确提示，不冒充发行包参数全集。Apache 继续从包内模板建立独立配置，并支持 config/overrides/apache.conf 作为首次配置片段。

删除组件包意味着同时移除其中的正式配置与扩展；同名新包只使用新包自己的配置或模板。PHP、MySQL、Redis 不自动导入 config/services 或 config/overrides 中遗留的旧配置，这些文件不自动删除。需要保留的自定义参数由使用者核对当前组件兼容性后添加。软件设置中的端口、项目绑定和 MySQL 数据目录仍独立保存，不因重装包清空数据。

PHP 网站进程显式加载包内 php.ini；CLI 在未被 -c、PHPRC、注册表等设置覆盖时可从程序目录找到同一份文件，仍须选用正确的 php.exe。修改后 CLI 下次执行读取新配置，运行中的网站需应用或重启后验证。读取时的文件准备与运行配置生效分别处理，应用仍需走校验和恢复管线。

## 8. 配置生效与根目录问题

所有变更经过统一管线：

1. 更新期望配置并记录版本号，计算受影响实例和站点。
2. 校验目录、域名、端口、运行包引用和参数。
3. 生成候选配置；Apache 使用目标二进制对候选配置执行语法检查。
4. 保存上一份可用配置，原子替换应用层配置指针或文件。
5. 项目路由和 Apache 原生配置使用 Apache 重加载；PHP ini 只重启对应进程池，MySQL/Redis 只正常重启被修改的实例。已停止服务保持停止，运行中的 Apache 按需启动新依赖的 PHP，不停止其他实例。
6. 验证进程、服务、站点根目录标识和实际 PHP 版本。
7. 成功后更新“已应用版本”；失败则尝试恢复上一份可用配置，并显示恢复是否成功。

期望配置、磁盘完整配置和实际运行状态分别记录，UI 显示“待应用 / 应用中 / 已生效 / 失败”。保存文件成功不能直接显示为运行成功。手动修改的完整文件也需检测并进入同一管线；自动检测未实现时通过主动应用、重启或 Apache 重加载处理。

全局 www 根目录变更只影响明确继承它的项目；固定路径的项目保持自己的路径，并在变更预览中列出。这一规则避免全局根目录与项目根目录产生隐含覆盖。

控制操作按实例串行处理；重复点击不产生第二个进程。进程身份记录可执行文件路径、启动时间、PID 和实例标识，不能仅凭名称或过期 PID 管理进程。启动过程中端口仍可能被抢占，因此预检查后也必须校验最终启动结果。

保存一次即完成校验、应用和验证，界面显示进行中的操作及结果；失败保留表单编辑内容并说明恢复结果和重新保存方式。Apache 重加载不保证长请求完全无中断，PHP 进程池更新可能短暂影响共用该包的网站。

## 9. 面板交互

服务管理、项目管理和环境设置采用紧凑的单行标题区，仅展示页面标题及相关操作按钮，不在标题下添加介绍语。

服务列表按组件 / 实例、使用方式、端口、状态、操作排列，表头与数据行共用列宽、间距及滚动区域宽度。名称左对齐，使用方式、端口、状态和操作水平居中，各列内容垂直居中；长名称省略，多端口允许换行。使用方式来自已保存的配置，“常用”用淡紫色文字标签强调，“普通”采用中性文字，停用服务不显示。状态颜色依据状态文本判定，异常不能因进程尚在运行而显示绿色。

页面沿用浅色侧栏与卡片，卡片边框保持一致。筛选选中使用浅色强调，主要启动和提交操作使用实色按钮；按钮的键盘焦点以边框提示。

主面板的配置状态使用“配置已保存，待启动验证”“配置已保存，待应用”“配置已生效”等直接表述。内部配置版本号用于判断保存与生效状态，不在日常状态栏展示；失败时保留具体错误和恢复结果。

环境设置按“启动设置”“网站服务与默认 PHP”“PHP 运行设置”“MySQL 服务”和“Redis”组织；MySQL 区域说明每项服务独立保存数据、配置和端口。项目页使用“网站入口目录”和明确的 PHP 包选择。“从列表移除项目”明确保留项目文件，“撤销未保存的修改”恢复已保存的表单值。配置编辑器使用“检查并应用”和“没有未保存的修改”；域名映射预览说明管理员授权及仅更新本环境记录，操作名称与“应用域名映射”按钮一致。

项目页必须明确选择具体 PHP 包，默认 PHP 设置不改变已保存项目。端口输入框留足五位数字的显示空间；PHP 每个版本分为名称行和参数行，使用方式、起始端口、进程数之间保留明确间距。每个模块提供“打开服务目录”入口，打开环境内对应的 bin/apache、bin/php、bin/mysql、bin/redis 目录；此导航操作运行中仍可使用，打开前校验目录归属与重解析点。

项目、PHP 目录入口和安装位置使用资源管理器式目录选择窗口，支持地址栏粘贴完整路径、返回与前进、查看文件列表；“使用当前目录”返回当前文件夹，选择文件时返回所在目录，不打开或修改文件。确认后仍执行对应的中文路径、目录边界与重解析点检查。开发隔离模式限制导航范围，产品正常使用允许选择本机业务目录。

MySQL 表单仅自动检测新增服务的数据目录，修改名称或新增行的版本后更新提示；已保存服务可主动点击“检查目录”和“接入数据”；默认展示配置中的路径，页面加载、状态刷新及端口、使用方式修改不读取目录内容。保存时仅检查新增或目录身份变化的服务；启动时仍验证数据目录完整性、版本绑定及初始化条件。

左侧导航采用随程序嵌入的 SVG 图标，服务、项目、环境设置和关于分别使用服务器、文件夹、齿轮和信息图形。图标统一尺寸、线宽与对齐方式，颜色跟随导航选中状态，不使用字体符号充当图标。

主面板按“服务 / 项目”分页。服务页显示实际版本、实例、端口和状态，提供全部及选中实例的启停、配置、日志与组件详情；项目页提供编辑、保存应用、打开站点和域名映射。环境设置管理默认 PHP、端口、进程池、MySQL 实例及四类服务的使用方式。托盘提供打开、启停和退出；关闭窗口隐藏到托盘。服务页默认全部，可按 Apache、PHP、MySQL、Redis 筛选；筛选不改变全局启停的作用范围。服务主名称使用组件顶层文件夹名，版本、实例标识和端口辅助区分；目录名称不作为数据库数据迁移许可。右键菜单支持启停、重启、配置和日志；Apache 可校验后重加载并验证，其他组件通过重启应用完整配置。首版不展示终端入口。

“项目”窗口提供显示名称、访问标识、分组、项目目录、网站入口目录、PHP 选择、启用访问、局域网访问、导航页展示和可选域名虚拟主机。支持搜索、共享状态筛选、批量设置共享、保存、移除、打开站点、复制地址及导航页入口。

所有服务使用“常用 / 普通 / 停用”三段按钮，三者互斥。版本字段使用“选择”按钮打开独立列表面板，标出当前版本，允许取消并保留原值。版本面板独立于设置行，后台校验与状态刷新只更新原列表的对应行，避免打断文本输入和版本选择。“启动常用 ▾”的主操作只启动常用服务，右侧 SVG 箭头菜单提供“启动全部”，包含普通服务。停用服务不显示、不计数且不能启动；标签数量按可见服务实例统计，PHP 进程池计为一项。Apache 启动时自动带起启用目录入口及项目所需的普通或常用 PHP，依赖被停用时在批量启动前拒绝。停止共享实例时列出受影响项目。

环境设置中运行中的服务及被运行网站依赖的对应项锁定，禁止编辑、移除和改变使用方式；后台按实时进程状态复核。保存已停止服务的设置不重启其他服务。MySQL 使用带表头的列表，列为使用方式、数据目录名称、版本、端口和操作；行下显示完整数据路径和状态，新行使用浅色背景及“新增 · 未保存”标记。已保存行移除前确认并说明数据保留位置，未保存行提供“取消新增”。

首版包含端口诊断、运行日志、配置入口和 hosts 映射。项目终端、便携迁移、HTTPS、PHP 扩展开关、数据库导入导出助手作为后续可选功能，在核心稳定后按需要追加。Node.js 等其他组件不纳入首版菜单，内部适配器接口保留扩展能力即可。

## 10. 模块职责

| 模块 | 职责 |
| --- | --- |
| Core | Package / Instance / Project 模型、路径解析、持久化 |
| Discovery | 包发现与版本能力探测 |
| ProcessSupervisor | 进程身份、状态机、超时、日志和退出处理 |
| ApacheAdapter | 虚拟主机、语法校验、配置应用和站点验证 |
| PhpAdapter | ini、worker 生命周期、FastCGI 诊断 |
| MySqlAdapter | 数据目录绑定、初始化、启动、健康检查、正常关闭 |
| RedisAdapter | 单实例发现、配置、启停、PING 健康检查、日志和持久化状态 |
| WindowsPlatform | windows-rs、Win32 API 封装、句柄生命周期、进程与窗口通知 |
| Desktop | Slint 主面板、Scintilla 编辑器、后台有界通道、托盘、菜单、项目管理 |
| PrivilegedHelper | 限定范围的 hosts 变更；后续证书信任 |

模块集成需覆盖多个 PHP 站点、两个隔离 MySQL 实例和一个 Redis 实例同时运行及正常停止，同时验证面板操作、组件发现、配置生效和异常恢复。项目终端、便携迁移及其他可选功能不作为首版交付条件。

## 11. 验收要求

以下内容是验收要求，不是已通过的测试结果；验证状态以对应测试证据为准，未完成验证见 PLAN.md。

- PHP 7.4、8.3、8.5 三个测试站点同时返回预期版本。
- MySQL 5.7 与选定的 8.x 构建同时运行，读写独立数据并能够正常关闭、重启。
- 两个相同 MySQL 版本的实例也能隔离运行。
- Redis 单实例可发现、启动、PING、读写、正常关闭及重启；启用持久化时验证数据恢复，修改配置后验证实际生效，端口冲突及关闭失败能准确报告。
- 不同 PHP 版本的测试项目可通过各自兼容的客户端连接共享 Redis；Redis 不要求多版本切换或并行运行。
- 两类 Apache 入口可同时运行；无受管理项目时版本目录入口仍能启动所需 PHP。
- 默认不生成项目域名虚拟主机；显式开启后域名与项目路径均按配置访问。
- 项目导航页搜索和分组、直接路径、隐藏项目、未知路径 404 及访问范围生效。
- Apache Rewrite、CakePHP 子目录及 webroot、Laravel public 目录、PATH_INFO、静态资源、Session、上传及并发请求正常。
- 修改根目录后请求命中新目录，修改 ini 后运行进程反映新值。
- 错误配置保留上次可用服务或明确报告恢复失败。
- 端口冲突、依赖缺失、失效 PID、快速重复点击、子进程崩溃均有准确状态。
- 实例数据不共享、不自动跨大版本启动；已有非空目录不被误初始化。
- 可选便携迁移验收：完整停止后从 D 盘复制到另一兼容电脑的不同路径，重新配置机器级依赖后可启动；不作为首版交付条件。
- 可选项目终端验收：从项目打开的终端使用对应 PHP，CLI 与站点绑定一致，且不同终端互不影响；不作为首版交付条件。
- 含空格的目录路径有实测结果；中文目录在创建、配置保存、组件扫描和部署目标检查时明确拒绝。
- 原生界面在 Windows 10/11 的常用 DPI 缩放下可用，托盘可恢复窗口，后台启停和扫描不阻塞交互。
- Release 构建记录冷/热启动至可交互的时间、窗口显示及托盘状态下的空闲 CPU 与内存。单独记录管理器及其辅助进程的占用，与 Apache/PHP/MySQL/Redis 分开统计；性能预算在最小原型实测后确定，不以语言特性代替测量。
