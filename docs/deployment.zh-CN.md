# 安装与升级方案

安装与升级使用同一个原生 EXE，安装包仅含软件本体。升级必须明确指定软件位置，未退出则提示并终止更新，不支持版本回退。本文描述部署规则及操作流程，实际验证范围以对应发布验证证据为准，待验证项目见 [PLAN](../PLAN.md)。

## 目标与发布产物

面向 Windows 10/11 x64，沿用 Rust 与 Slint 原生桌面路线。统一包携带完整软件文件，在新空目录安装，在已有有效安装目录按清单升级。源码、发布产物和日常使用目录分开，开发构建不能覆盖日常使用程序。

以下为统一包命名规则；生成命令见[打包操作](packaging.zh-CN.md)。

| 产物 | 命名 | 用途 |
| --- | --- | --- |
| 安装与升级 EXE | `Flaragon-Setup-<版本>-x64.exe` | 空目录新装、已有安装升级、同包中断续修 |

统一包包含软件本体：Flaragon.exe、实际运行需要的编辑器 DLL、第三方许可及发布清单。不包含 Apache/PHP/MySQL/Redis、源码、测试工具、开发说明、用户配置、数据库或网站。组件由用户自行解压添加。

首版只提供本地离线包，不包含在线自动更新、二进制差分、卸载器或数据库迁移。使用安装升级包不需要开发工程或 Rust，不依赖 BAT、PowerShell 脚本。

## 指定软件位置与多套环境隔离

升级界面的“软件位置”初始为空，用户必须明确选择含 Flaragon.exe 和有效发布清单的安装目录。不能根据升级包位置、工作目录、PATH、注册表或扫描结果自动决定目标，不提供批量升级入口。

未填写软件位置时也可直接点击“选择目录”，打开 Windows 原生目录选择窗口；取消不改变输入。初始浏览位置不作为安装目标，只有用户确认选择后才回填并按部署规则校验。

选择后展示完整安装路径、当前版本、目标版本和更新范围，用户点击“开始升级”才执行。长路径须可完整查看或复制，不能只显示文件夹名。更换目录立即清除检查结果，重新核验。

核验产品标识、安装标识、架构、版本、程序文件归属及路径安全；只读解析 EXE 的 x64 PE 标记、ProductName、ProductVersion 和 OriginalFilename，并与清单核对全部程序文件的存在及大小，不执行所选旧 EXE。仅存在同名 EXE 不能证明产品身份。首次安装生成独立安装标识，升级保留该标识。执行前重新确认规范化路径、目录身份及清单未变化，拒绝重解析点和路径重定向。一次只锁定并操作所选目录，其他安装目录的软件与服务不受影响。

无发布清单、源码目录、其他软件目录或身份无法确认的目录均拒绝升级。从首次正式安装建立升级链路，不提供无清单旧目录的自动接入。

## 文件范围

| 内容 | 安装行为 | 升级行为 |
| --- | --- | --- |
| Flaragon.exe、指定的 lib/ 文件和许可 | 解压创建 | 按白名单替换 |
| release.json | 记录产品、版本、架构及文件归属 | 自检成功后提交新版清单 |
| .flaragon-install.json | 生成独立安装标识 | 保持不变 |
| bin/ | 创建空组件目录 | 保留组件 |
| config/ | 首次正常运行生成 | 首版原样保留，检查格式兼容性 |
| data/、www/、环境外项目 | 不包含既有内容 | 不覆盖、不迁移、不读取业务内容 |
| logs/、runtime/ | 运行时按需生成 | 不写入或删除，仅读取必要的进程身份记录 |
| .maintenance/ | 部署操作按需创建 | 新版暂存文件、目标版本及事务进度 |

实际写入和删除入口再次执行程序路径白名单。data/（含 MySQL 数据、Redis RDB/AOF）、bin/ 内组件及原生配置、config/、www/、logs/ 和 runtime/ 均不作为升级写入或删除目标；不遍历或读取数据库文件，不启动数据库做迁移。

不能直接解压覆盖整个环境。移除废弃程序文件须同时符合旧清单归属与本次明确声明；跨版本包需要覆盖受支持旧版本的废弃文件集合。未知文件保留，目标冲突则中止。发布脚本仅按白名单组包，不能直接压缩整个开发或使用目录。

## 安装流程

1. 展示产品版本与内容，用户选择空目录或尚不存在的新目录。
2. 检查路径、权限、空间及包完整性，拒绝盘符根目录、系统目录、源码目录和未知非空目录。
3. 在目标卷暂存、解压并验证完整程序文件集合及路径边界，再写入目标。
4. 完成程序自检，生成安装身份与发布清单，展示结果及完整安装位置。
5. 提供“打开 Flaragon”，由用户决定是否启动。

默认不要求管理员权限，不修改系统 PATH、hosts、注册表或 Windows 服务，不安装系统运行库，不自动开启软件自启。组件依赖独立诊断，安装成功不代表所有组件已经可运行。

## 升级流程

安装与升级使用同一个完整 Setup 包，按目标目录识别新安装、升级或中断续修。兼容范围由 release-policy.json 显式指定 minimum_version 和 excluded_versions，支持范围内跨版本直升；同版本仍须明确绑定构建，降级拒绝。现有已发布归档保持自身规则，不因源码修改而改变。

选择目录后自动展示“开始安装”或“开始升级”；未完成事务显示继续操作。仅存在部分身份文件或清单损坏时拒绝，不能降格为新安装。0.0.4 及更早归档仍按各自包内规则执行。

0.0.5 统一 Setup 支持最低版本至 0.0.5 之前的兼容来源，并接受包内 update-base.json 明确绑定的原始 0.0.5。同版本覆盖保持产品版本、配置格式、程序文件集合和配套依赖；目标包可声明新的升级兼容范围。安装身份、配置、组件、项目和数据保持不变；重复或不匹配构建拒绝。原始 0.0.5 包独立归档至 dist/archives/original-0.0.5。

1. 用户在目标环境执行“停止并退出”，运行升级 EXE 并明确选择软件位置。
2. 展示路径和当前及目标版本，核验身份、版本兼容性、配置格式、文件集合、权限与空间。
3. 取得目标目录的独占部署锁，阻止该目录的管理器、CLI 或其他升级器并发进入；执行前复核目标身份。
4. 检查目标管理器、编辑器和受管服务均已退出。未退出时提示“该目录的软件或服务尚未退出，已终止更新。请执行‘停止并退出’后重试。”并终止，不覆盖程序文件，不自动停服或强杀。
5. 服务归属依据本环境记录的 PID、启动时间、程序路径等核验；不通过进程名或端口猜测，不探测其他环境。状态无法确认也终止更新。
6. 完整暂存并校验新版文件，持久记录目标版本及事务状态，然后按白名单替换。
7. 执行专用自检，仅检查版本、DLL 和配置可读性，不启动服务、不执行组件、不改写配置。
8. 自检成功后提交新版清单及完成状态，清理本次暂存内容。用户点击“打开 Flaragon”才正常启动，仍遵守常用服务自启设置。

升级 EXE 不得位于待替换清单内。不通过系统重启延迟覆盖，不修改其他安装目录的自启设置。

## 专用同版本修复

用户明确要求不发版修复时，使用独立的 `update.exe` 修复入口，产品版本保持不变。此入口与普通升级分开：包内包含完整适用安装清单，必须与目标安装的产品、版本、构建标识和程序文件清单一致；只有对应的指定基线安装可接受修复。基线可以是原始正式安装，也可以是已归档修复包的结果构建，必须逐一明确绑定。修复后提交独立构建标识，重复应用、其他同版本构建、其他版本及未知目录均拒绝。未携带原始构建绑定的普通升级继续拒绝同版本，所有升级均拒绝降级。

修复包沿用安装身份、目录与文件占用检查、明确目录选择、配置兼容检查、白名单替换、自检和持久事务。配置与数据原样保留，不自动停止服务。中断后仅允许基线清单、目标构建及全部暂存文件都一致的同一修复包续修。更高版本的正常升级仍可接受符合兼容范围的已修复安装。

PHP 完整版本修复包针对原始 0.0.1，文件为 `dist/repairs/php-version-0.0.1/update.exe`；正式 0.0.1 归档保持不变。生成及使用步骤见[打包操作](packaging.zh-CN.md#不发版的专用修复包)。

Redis 认证与组件刷新补丁针对原始 0.0.2，文件为 `dist/repairs/redis-refresh-0.0.2/update.exe`，修复后产品版本仍为 0.0.2，使用独立构建身份识别补丁；正式安装升级包与已发布的 0.0.2 日志保持不变。补丁功能单独记入 CHANGELOG 的补丁条目，交付后同样固定，不回写原版本日志。

已归档补丁 `dist/repairs/latest-dev-0.0.2/update.exe` 适用于原始 0.0.2；已应用 Redis 认证与组件刷新补丁的安装使用 `dist/repairs/latest-dev-from-redis-refresh-0.0.2/update.exe`。两者包含相同主程序，但适用构建不同，不可互换。升级至 0.0.3 使用普通 Update 包，无需先安装这些同版本补丁。

## 禁止回退与中断处理

- 不提供降级、“恢复上一版本”或回退入口，不保留用于产品回退的旧版本副本。
- 跨版本更新要求目标版本高于已安装版本；同版本仅允许包内明确绑定的原始构建覆盖，重复更新及不匹配构建拒绝，低版本明确拒绝。按版本数字比较，不依赖文件名或字符串排序。
- 覆盖前检查失败直接终止，原程序文件不变；覆盖开始后失败，不自动恢复旧版文件。
- 多文件替换可能中断，开始前必须持久记录原版本、目标版本、安装身份及新文件清单。存在未完成事务时，主程序拒绝普通启动，避免混用文件。
- 中断后只允许匹配原事务的同一目标版本发布包继续完成更新。这是未完成事务修复，不开放普通同版本重装；不能仅凭版本相同接续任意载荷。
- 修复时重新核验目录身份、退出状态及文件完整性，要求重新提供的包与完整暂存载荷逐文件一致，再补齐目标程序并完整自检。不能仅因 EXE 已替换为新版就判定完成。暂存内容损坏或丢失时拒绝自动续修，避免将不同载荷当成同一事务；此类存储故障需要单独诊断。
- 自检失败、磁盘或权限问题未解决时，保留未完成状态并说明原因，不启动软件、不报告成功。排除问题后重新运行匹配的升级包修复。
- 不支持回退意味着覆盖中断后软件可能暂时不可用，直至目标版本修复完成；配置、组件和业务数据仍受保护。

## 升级兼容范围

统一包接受 minimum_version（含）至目标版本（不含）的来源，排除 excluded_versions；不要求逐版安装。授权的同版本覆盖另以包内原始清单绑定。完整载荷不能代替配置和目录格式兼容验证。

| 情况 | 处理 |
| --- | --- |
| 兼容范围内旧版本，配置格式兼容 | 允许直接升级 |
| 同版本包 | 仅明确绑定的原始构建允许覆盖；重复或不匹配构建拒绝 |
| 更低版本包 | 拒绝，不支持降级 |
| 低于 minimum_version 或位于 excluded_versions | 写入前拒绝并显示范围 |
| 配置格式不兼容 | 写入前拒绝；当前不实现格式迁移 |
| 无清单或身份不明 | 拒绝升级 |

发布清单记录产品版本、发布身份、架构、包格式、程序文件集合、minimum_version、excluded_versions 和 config_schema。release-policy.json 显式维护最低版本、排除项及受支持来源的累积废弃程序文件；新增正式版本不会自动提高最低版本。config/app.json 的 schema 是配置格式，revision 是修改次数，都不是软件发布版本。

当前 schema 1 配置通过兼容读取保持字节内容，不迁移配置格式或数据库。未知 schema 在写入前拒绝。软件升级与 PHP/MySQL 等组件升级分开。界面、EXE 元数据、包名和清单的版本须一致；归档完整性检查不能冒充发布者身份认证。

0.0.4 的 PHP、MySQL、Redis 配置由组件包维护，旧 config/services 和 config/overrides 中相应文件保留但不自动导入；升级后应通过配置入口核对包内实际配置及自定义参数。Apache 继续使用独立配置。环境及其父目录、组件、项目、网站入口和 MySQL 数据目录均不得含中文，升级目标检查会拒绝含中文的环境路径。

## 开发边界与验收计划

日常目录由用户选择，例如 D:\Apps\Flaragon，这是设计示例，不在本任务创建或访问。开发输出及验证仅使用 D:\flaragon_dev 内的夹具，保留 FLARAGON_DEV_ROOT。现有环境的组件、配置、数据库和项目搬迁是独立任务，安装升级包不自动收集或搬迁。

以下为验收要求，结果以对应发布验证证据为准，尚未验证的范围见 PLAN：

- 空格路径、新安装、中文目录及中文父目录拒绝、非空或未知目标拒绝、无清单拒绝。
- 多套安装只更新所选目录；改选目录、路径重定向及检查后身份变化的保护。
- 管理器、编辑器或受管服务未退出时终止且程序文件不变；其他环境不被误判或操作。
- 指定原始构建同版本覆盖、重复及不匹配构建拒绝、降级拒绝、兼容范围内跨版本升级、不兼容路径在写入前拒绝。
- 配置、自启选项、组件、会话文件及业务数据保持，废弃程序文件按清单处理。
- 损坏包、路径越界、权限及空间不足、覆盖中断、自检失败；只能继续目标版本修复，无回退入口。
- 发布包内容、真实窗口、Windows 10/11 和跨电脑部署分别验证，构建成功不能替代部署验收。

## 构建与打包

打包命令、准备条件及产物命名见[打包操作](packaging.zh-CN.md)。

发版指令和发布版本号均由用户明确指定，日常修改、Git 提交及开发用 Release 构建不自动发版或递增版本号。收到发版指令及版本号后同步产品版本与相关文档；[更新说明](../CHANGELOG.md)按版本概述最终实现的功能、改进与问题修正，不记录开发调试过程。仅当前开发版本允许修改，实际发布前保留“未发布”标记；发布完成后固定该版本日志；用户明确授权同版本合并替换时，合并指定版本内容并独立保留原始包和说明，其他版本不变。后续开发在顶部新增“未发布”部分。

在项目目录运行 `scripts/package.ps1`，执行格式检查、Clippy、测试、Release 构建、许可收集、自检及组包。已经检查和构建完成时可用 `scripts/package.ps1 -SkipBuild`。产物位于 `dist/<版本>/`，构建脚本不会覆盖环境根目录的 Flaragon.exe。

产品版本使用用户指定并写入 Cargo.toml 的值，同步 Cargo.lock 中本项目版本，并统一写入 EXE 版本信息、界面、包名和发布清单。每份发布归档的载荷保持固定；组包检测到已有归档内容变化时拒绝覆盖，新版本号须由用户指定。用户明确要求同版本重打包时，通过独立构建标识和新的发布身份另存至 `dist/rebuilds/<构建标识>/`，保留原始归档及补丁绑定。同版本覆盖须由用户明确授权并在包内绑定原始构建；用户授权的 0.0.5 候选通过验证后可替换正式入口，原始归档独立保留。归档仅接受普通文件，限制大小及数量，拒绝路径越界、大小写冲突和文件目录冲突。版本数字逐段比较，不使用字符串排序。

生成的包尚未进行代码签名。目录身份检查用于防止误选及不完整部署，不等同于验证发布者签名；完整性检查不能证明包的发布者可信。

Win32 版本资源与目录身份查询依据微软的 [VerQueryValueW](https://learn.microsoft.com/en-us/windows/win32/api/winver/nf-winver-verqueryvaluew) 和 [GetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle) 文档实现。
